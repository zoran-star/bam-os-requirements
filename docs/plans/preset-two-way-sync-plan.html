03How the check decides what is real

A GTA literal in a source file is not evidence of a leak. Three false positives in one day came from assuming it was. This is the rule that separated live from dead in every case.

Does anything override this value on the path to output, and does that override fail open or closed?

Grepping for literals finds text. Tracing overrides finds leaks. The checker traces the path, it does not scan for strings.

04One principle covers both surfaces

Everything below is an application of a single rule.

The rule
No fact, no output.

A default may never contain a real academy's fact. Where a fact is missing, the thing that needed it renders nothing at all, rather than falling back to somebody else's version of it. In an email that means the block does not appear. In the agent brain it means the section is absent from the prompt. Same rule, two surfaces.

Defaults go neutral-or-empty

Zoran's call. The fail-open stays, because an agent with no fallback improvises, which is worse than a gap. What changes is that falling open becomes harmless.

Emails become blocks

A block declares the fact it needs. No fact, no block. Nine blocks for every academy, and each academy renders the ones it can fill.

A test enforces it

Assert that no default body contains an academy identity value. That is what stops this recurring, not the cleanup itself.

So convergence separates three things, not two

Structure (step count, timing, channel, which template a step points at) converges freely. Tokenized copy converges once genuinely academy-neutral. Attributed content (real people's words, named coaches, addresses, photos) never propagates and must be impossible to pick up by accident.

07The eight calls

Made with Zoran, 27 Jul 2026.

01 · Authority
GTA is the reference implementation.

The master equals GTA's live automation system with identity templatized, not a separately-authored lighter version. A gap is a master bug to close. The trade, accepted knowingly: GTA becomes a governed instance. Every edit to GTA's rows is a claim on every academy, and GTA's 4 hardcoded sales steps stop being GTA's business and become bugs to fix.

02 · Where the check fires
Weekly GitHub Action that opens and updates one issue.

Reverse pass added to the existing script, scheduled in .github/workflows, keeping a single issue titled "Preset drift" current rather than opening a new one weekly. It lands in the repo where the fix lives and needs nobody to remember to look.

03 · How the check decides
Trace overrides, never grep literals.

A value is flagged only when nothing overrides it on the path to output, or when the override fails open. Comments, deleted fallbacks and unconditionally-replaced defaults are reported as dead rather than passed over in silence, so the checker is trusted instead of tuned out.

04 · The brake on attributed content
A sync_class marker: shared / local / attributed.

Set on the template so every step pointing at it inherits. Default is shared. local means structure is shared but the words belong to this academy. attributed means it never propagates and must be re-authored. Attached to the smallest addressable unit, so it works for a step, a block, an offer or a pipeline stage.

05 · The agent brain's fail-open
Make every default neutral-or-empty. Keep the fail-open.

Failing open is the right behaviour, because an agent with no fallback improvises. The bug is what it falls back to. Once no default carries a real academy fact, falling open is harmless, and a missing fact renders nothing instead of GTA's version.

06 · The three GTA-shelled emails
Re-shell all three, and collect the missing facts in onboarding.

onboarding-welcome, -training and -review build their own header and footer with GTA's wordmark, "OAKVILLE · GTA", the GTA domain and GTA's Instagram baked in as literals, instead of using the tokenized shell that already exists. Re-shelling is plumbing, not copywriting.

07 · Composition and owner copy
Blocks auto-render when their fact exists. Copy changes go through support tickets.

Filling the wizard is composing the email, so there is no extra step, but the wizard has to actually ask or auto-on silently means auto-off. No free-text override in the product: routing copy changes through tickets keeps every word staff-authored and therefore promotable, and puts the promote-or-hold decision exactly where someone is already making a judgment.

08 · The two orphan sequences
Delete Trial Follow-up. Summer Special stays GTA-only, parked.

Neither has ever enrolled a single lead. Trial Follow-up duplicates trial_form, same trigger and same 20-minute wait, and trial_form has run 30 times including today. Summer Special is held pending a standardized reignition flow for sales presets, recorded as an accepted exception so the check stops nagging and it resurfaces when that work starts.

12The guardrail this plan is held to

Sales systems are shared. Never fork one academy's structure.

If one academy needs X, either every academy gets X or X is a runtime fact. It is recorded as an ACCEPTED divergence with that reason attached rather than left as silent drift, so it resurfaces the moment the reignition work starts.

13Build spec

Two waves. Wave 1 converges the master to GTA minus identity. Wave 2 keeps it there. Severity uses the standing triage: BLOCKER, FRICTION, SCALE.

H. Neutralize the agent brain's defaults BLOCKERwave 1

The only item leaking to every academy right now, unconditionally, with no seed step in between. Do this first.

Build

  • Give social_proof a renderer in fact-render.js fed by the new review-link field, and add it to the set() list. With set() already skipping falsy bodies, an academy with no link renders nothing, which is the correct outcome.
  • Sweep every default body in prompt-structure.js for real academy facts and replace them with neutral-or-empty. program, schedule, pricing, policies and coaches all currently carry GTA's answers. The coaches default asserting every coach played at college or professional level is a false claim for a new academy, not just a leak.
  • Keep both fail-open returns exactly as they are. Per Zoran's call the fallback is correct once what it falls back to is harmless.
  • Add the test that asserts no default body contains an academy identity value, drawing the identity set from the same place email-shells.js resolves it.

Done when

An academy with no training offer produces a prompt with those sections absent rather than populated with another academy's answers, and the test fails if anyone reintroduces a literal.

A. sync_class and the testimonials brake BLOCKERwave 2, gates D

Must land before or with item D. Without it the promotion is itself the bug.

Build

  • Add a sync_class declaration to the template registry in api/email-templates/. Three values: shared (default), local, attributed.
  • Mark onboarding-testimonials and nurture-3 as attributed.
  • Add sync_class to automation_steps, default shared. A step whose body is template:<key> inherits the template's class, so the marking lives with the content and cannot be lost by editing a step.
  • Seeder rule: a step whose resolved class is attributed seeds enabled:false with a note telling the academy to supply their own.

Done when

A freshly seeded academy has the testimonials step present and disabled, and San Jose's existing deliberate hold reports HELD rather than drift.

G. Clean GTA's own rows SCALEwave 1, do first

Small, independent, and makes every later run cleaner. Follows directly from GTA being the reference.

Build

  • Delete the trial_followup automation and its single step. Zero enrollments ever, disabled, never approved, duplicates trial_form which has run 30 times including today, and its body references a token that does not resolve.
  • Replace hardcoded academy literals with the tokens the master already uses, in contact_form step 1, trial_form step 1, and ghosted steps 1 and 2.
  • Record summer_special as an ACCEPTED divergence, reason "held pending a standardized reignition flow for sales presets".

Done when

GTA reports MATCH on every sales key, with no EXTRA rows other than the recorded exception.

F. Collect the four missing facts in onboarding FRICTIONwave 1, gates E

Zoran's condition on the auto-on decision: the wizard has to actually ask, otherwise auto-on silently means auto-off.

Build

  • Four new fields: Google review link, community group link plus platform label, online programs URL, refer-a-friend perk text. Plus filling clients.phone, which exists and is empty for GTA.
  • The onboarding wizard rule applies in full: a registry row in _OBF_STEPS, a detector in _obfFetchState(), and the key listed in a section's keys in _OBF_SECTIONS. All three, or the step is defined and detected but invisible.

E. Re-shell and block-ify the three GTA-shelled emails FRICTIONwave 1, needs F

The largest item.

Build

  • Delete the local HEAD and FOOT in api/email-templates/onboarding-emails.js and render all three through the tokenized shell email-shells.js already fills. This alone removes the GTA wordmark, the "OAKVILLE · GTA" tag, the GTA domain and GTA's Instagram from three emails.

  • onboarding-review: re-shell, point the call to action at the review-link field. No field, no button.

B. Override-tracing reverse check SCALEwave 2

Build

  • Declare the reference academy explicitly, GTA today, rather than inferring it.
  • Replace the single EDITED verdict with AHEAD, BEHIND, HELD, ACCEPTED, LEAK and DEAD, keeping MATCH, MISSING and EMPTY as they are.
  • AHEAD when the reference has structure the master lacks: more steps, a template reference the master does not carry, a different channel or timing. This is a structural diff and needs no literal scanning.
  • BEHIND, LEAK and DEAD all come from override tracing, never from grepping. For each default, resolve whether an override exists on the path to output and whether it fails open or closed. No override, or an override that fails open, is a LEAK. An override that replaces unconditionally makes the literal DEAD, and DEAD is reported rather than hidden so the same false positive is not raised twice.
  • HELD when the differing content resolves to attributed or local.
  • ACCEPTED from a small file of recorded divergences, each requiring a written reason. Seed it with summer_special.
  • Exit 1 on AHEAD, BEHIND, LEAK, MISSING or EMPTY.

Note

Keep the verdict set generic. A parallel audit covers stages, entry points, agents, calendars and offers, and those entities feed the same reporter with the same verdicts.

C. Weekly drift issue SCALEwave 2

Build

  • Workflow in .github/workflows/, weekly schedule plus manual dispatch, running the checker with --all.
  • Find the open issue titled "Preset drift" and edit its body, or open it if absent. One issue, always current, never a weekly pile.
  • Body groups by verdict with the academy, the key and the suggested action. Close automatically when a run comes back clean.
  • Needs the service key as a repo secret, read-only. The script never writes to the database.

What changes for every future academy
  • A new academy seeds an 8-step onboarding instead of 3, with 5 designed emails live and the testimonials step present but off until they supply their own.
  • The agent goes live with facts it actually holds, and stays silent on the ones it does not, instead of answering with GTA's program, pricing and coaching claims.
  • Onboarding asks four new questions, each visibly turning on a block of the welcome email, and one of them also turns on the agent's social proof.
  • Copy change requests arrive as support tickets, and each ticket is the moment staff decides master-for-everyone or recorded divergence for one.
  • Drift in either direction, plus any new leak, surfaces weekly in one GitHub issue instead of waiting to be noticed.
  • GTA is now governed. Editing GTA is editing the reference, and the check will say so within the week.
