The master can't see when GTA is ahead.

The divergence checker only looks one way. It catches an academy drifting from the shared defaults. It cannot catch the shared defaults falling behind what BAM GTA actually runs. That already happened, in the sequence that greets every new paying member.

Plan · 27 Jul 2026 · decisions locked with Zoran · facts verified against live prod rows

The cost, in plain terms

Every academy launched since the preset shipped, San Jose included, gets a 3-step SMS-only welcome while GTA's members get 8 touches and 6 designed emails. The 6 email templates were already built and already reachable. The master simply pointed at none of them.

There was already a rule

The header of form-intro-automations.js says good live edits must be promoted back into the defaults. It was written, never enforced, and never happened. A rule with nothing watching it is a comment.

03Why a naive two-way sync would have shipped the bad thing

   GTA's onboarding-testimonials carries REAL parent quotes.
   The academy name and city inside it are TOKENIZED, which is exactly what
   makes it dangerous: it renders cleanly for anybody.

        "Best decision we made for our son."
                        - Parent of Adam, {{location.city}}
                                            │
                                            └──▶ renders "San Jose"

   A San Jose parent reads a San Jose family praising a program they never
   attended. Zoran already caught this class of bug and deliberately held
   nurture-3 for San Jose. A structure-only diff would have called that
   hold "drift" and a naive sync would have undone it.
So the sync has to separate three things, not two

Structure (step count, timing, channel, which template a step points at) converges freely. Tokenized copy converges once it is genuinely academy-neutral. Attributed content (real people's words, named coaches, addresses, photos) never propagates and must be impossible to pick up by accident.

04The seven calls

Made with Zoran, 27 Jul 2026.

01 · Authority
GTA is the reference implementation.

The master is expected to match GTA's structure, tokenized. A gap is a master bug to close. The trade, accepted knowingly: GTA becomes a governed instance. Every edit to GTA's rows is now a claim on every academy, and GTA's 4 hardcoded sales steps stop being GTA's business and become bugs to fix.

02 · Where the check fires
Weekly GitHub Action that opens and updates one issue.

Extend the existing script with a reverse pass, schedule it in .github/workflows, keep a single issue titled "Preset drift" up to date rather than opening a new one each week. It lands in the repo where the fix lives and needs nobody to remember to look.

03 · The brake on attributed content
A sync_class marker: shared / local / attributed.

Set on the template so every step pointing at it inherits. Default is shared. local means the structure is shared but the words belong to this academy. attributed means it never propagates and must be re-authored. Attached to the smallest addressable unit, so it works for a step, a block, an offer or a pipeline stage, not just automations.

04 · The three GTA-shelled emails
Re-shell all three, and collect the missing facts in onboarding.

onboarding-welcome, -training and -review build their own header and footer with GTA's wordmark, "OAKVILLE · GTA", the GTA domain and GTA's Instagram baked in as literals, instead of using the tokenized shell that already exists. Re-shelling is plumbing, not copywriting.

05 · Composition
Blocks auto-render when their fact exists, and onboarding must guarantee the fact exists.

An email stops being one blob and becomes an ordered list of blocks. A block with no fact does not render, the same fail-to-empty rule already used for the website link. Filling the wizard is composing the email, so there is no extra composition step, but the wizard has to actually ask.

06 · Owner copy changes
Through the support ticket system, not a free-text field.

This keeps every word staff-authored, which keeps every word promotable. It also puts the promote decision in exactly the right place: when a ticket asks for a copy change, staff decides right there whether it goes in the master for everyone or is recorded as a deliberate divergence for that one academy.

07 · The two orphan sequences
Delete Trial Follow-up. Summer Special stays GTA-only, parked.

Neither has ever enrolled a single lead. Trial Follow-up is a duplicate of trial_form, same trigger and same 20-minute wait, and trial_form has run 30 times including today. Summer Special is held pending a standardized reignition flow for sales presets, and is recorded as an accepted exception so the reverse check stops nagging.

No fact, no block

The same fail-to-empty rule already used for the website link. No academy ever ships a broken or borrowed block.

They never get promoted into the master and never report as drift, so "the letter changes fully" needs no extra marking.

GTA-as-reference stays safe, because owner-specific blocks are excluded by construction rather than by anyone remembering.

09The guardrail this plan is held to

Sales systems are shared. Never fork one academy's structure.

If one academy needs X, either every academy gets X or X is a runtime fact. This plan takes one exception knowingly: Summer Special stays GTA-only, parked pending a standardized reignition flow for sales presets. It is recorded as an ACCEPTED divergence with that reason attached, not left as silent drift, so it surfaces again the moment the reignition work starts.

10Build spec

Seven items. Severity uses the standing triage: BLOCKER, FRICTION, SCALE.

A. Testimonials brake BLOCKER

Must land before or with any onboarding promotion. Without it the promotion itself is the bug.

Build

  • Add a sync_class declaration to the template registry in api/email-templates/. Three values: shared (default), local, attributed.
  • Mark onboarding-testimonials and nurture-3 as attributed.
  • Add sync_class to automation_steps, defaulting to shared. A step whose body is template:<key> inherits the template's class, so the marking lives with the content and cannot be lost by editing a step.
  • Seeder rule: a step whose resolved class is attributed seeds with enabled:false and a note telling the academy to supply their own.

Done when

A freshly seeded academy has the testimonials step present, disabled, and San Jose's existing deliberate hold reports as HELD rather than as drift.

B. Reverse pass in the divergence checker SCALE

Build

  • Declare the reference academy explicitly, GTA today, rather than inferring it.
  • Replace the single EDITED verdict with AHEAD, BEHIND, HELD, ACCEPTED, keeping MATCH, MISSING and EMPTY as they are.
  • AHEAD when the reference has structure the master lacks: more steps, a template reference the master does not carry, a different channel or timing.
  • BEHIND when the reference carries an academy literal where the master carries a token. Detect by scanning the reference's step bodies for known academy identity values, the same set email-shells.js resolves.
  • HELD when the differing content resolves to attributed or local.
  • ACCEPTED from a small file of recorded divergences, each requiring a written reason. Seed it with summer_special.
  • Exit 1 on any AHEAD or BEHIND as well as MISSING and EMPTY.

Note

Keep the verdict set generic. A parallel audit covers stages, entry points, agents, calendars and offers, and those entities feed the same reporter with the same five verdicts.

C. Weekly drift issue SCALE

Build

  • Workflow in .github/workflows/, weekly schedule plus manual dispatch, running the checker with --all.
  • Find the open issue titled "Preset drift" and edit its body, or open it if absent. One issue, always current, never a weekly pile.
  • Body groups by verdict with the academy, the key and the suggested action. Close the issue automatically when a run comes back clean.
  • Needs the service key as a repo secret, read-only. The script never writes to the database.
D. Promote the onboarding sequence FRICTION

Depends on A. Takes ONBOARDING_DEFAULT from 3 steps to 8.

Build

  • Promote GTA's structure and timings: 0m SMS, 0m welcome email, +5m schedule SMS, +5m training email, +3d story, +7d era, +7d testimonials, +7d review.
  • The schedule SMS renders from schedule_slots and does not send when the academy has no slots, rather than carrying pasted text.
  • onboarding-era promotes as-is. onboarding-story promotes after tokenizing one word.
  • Every step body stays a template:<key> reference so the database holds a reference, not markup.

Done when

A newly seeded academy shows 8 onboarding steps, the divergence check reports MATCH for the key against GTA, and the testimonials step is present and disabled.

E. Re-shell and block-ify the three GTA-shelled emails FRICTION

The largest item. Depends on F for the welcome email's owner-supplied blocks.

Build

  • Delete the local HEAD and FOOT in api/email-templates/onboarding-emails.js and render all three through the tokenized shell that email-shells.js already fills. This alone removes the GTA wordmark, the "OAKVILLE · GTA" tag, the GTA domain and GTA's Instagram from three emails.
  • onboarding-training: re-shell and change the sign-off to a token. Body is otherwise brand-global.
  • onboarding-review: re-shell and point the call to action at the new review-link field. No field, no button.
  • onboarding-welcome: rebuild as the nine blocks. Each block declares what it needs and does not render without it. Schedule and venue come from schedule_slots.

Watch for

The existing stripFreeTrial helper and dropEmptyShellLinks both operate on rendered markup. Blocks must be assembled before those run, not after.

F. Collect the four missing facts in onboarding FRICTION

Zoran's condition on the auto-on decision: the wizard has to actually ask, otherwise auto-on silently means auto-off.

Build

  • Four new fields: Google review link, community group link plus its platform label, online programs URL, refer-a-friend perk text. Plus filling clients.phone, which already exists and is empty for GTA.
  • The onboarding wizard rule applies in full: a registry row in _OBF_STEPS, a detector in _obfFetchState(), and the key listed in a section's keys in _OBF_SECTIONS. All three, or the step is defined and detected but invisible.
  • Show the owner what each fact turns on, so the connection between filling a field and the email a parent receives is visible at the point of action.
  • Backfill GTA's own five values, since GTA is the reference and has to be complete.
G. Clean up GTA's own rows SCALE

Follows directly from GTA being the reference. These stop being GTA's business and become bugs.

Build

  • Delete the trial_followup automation and its single step. Zero enrollments ever, disabled, never approved, and a duplicate of trial_form which has run 30 times including today. Its body also references a token that does not resolve.
  • Replace the hardcoded academy literals in the 4 sales steps with the tokens the master already uses: contact_form step 1, trial_form step 1, ghosted steps 1 and 2.
  • Record summer_special as an ACCEPTED divergence with the reason "held pending a standardized reignition flow for sales presets".

Done when

GTA reports MATCH on every sales key and no EXTRA rows other than the one recorded exception.

What changes for every future academy
  • A new academy seeds an 8-step onboarding instead of 3, with 5 designed emails live and the testimonials step present but off until they supply their own.
  • Onboarding asks four new questions, and each one visibly turns on a block of the welcome email.
  • Copy change requests arrive as support tickets, and each ticket is the moment staff decides master-for-everyone or recorded divergence for one.
  • Drift in either direction surfaces weekly in one GitHub issue instead of waiting to be noticed.
  • GTA is now governed. Editing GTA is editing the reference, and the check will say so within the week.

Every fact in this plan was verified against live production rows on 27 Jul 2026, not inferred from the code. Enrollment counts, step bodies, schedule slot counts and the address mismatch all come from the database.
