Build C
A re-run guard

Small but load-bearing: re-running a site build refuses to overwrite pages that carry newer hand-fixes, instead of silently clobbering them. See the collision below.

One collision, found while mapping, needs your ruling

Two things write the same website files, and a re-run eats the fixes

When a client asks for a page change, the website-fix loop edits their live pages directly. But re-running the core site build replaces those same pages wholesale from the kit. Any client-requested fixes made since the last build would be silently overwritten. Nothing guards this today.

Build C is the fix I recommend: the site build checks whether the client's pages carry fix commits newer than its own last run, and stops with a list of them instead of overwriting. Staff folds them in deliberately.

Smaller, same family: two unrelated things are both called "site pages"

The label list an owner edits in their Blueprint and the file map the deploy scripts push are different stores with the same name, and nothing reconciles them. Not urgent, logged so it stops surprising people.
