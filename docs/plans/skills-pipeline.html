Why the sales system is its own skill

One skill per sales system. Shared machinery underneath. Always.

More sales systems are coming, and each will need its own build process. So the free-trial build is isolated now: when sales system #2 arrives, it gets its own sibling skill with its own steps, and it drives the same message machinery, the same render path, the same locks. A new system is a new skill, never a fork of the machinery - that is the same rule that keeps one academy's structure from forking the preset.

So the build list is three things

Build A
The sales system skill

The gold steps in skill 3. The funnel-page half already exists and folds in; the messages half is new and drives the machinery built and locked this month. The two trial emails move in from the old email-templates skill; the member emails park with skill 4.

Build B
The owner approval step

One new step in the owner's wizard: they see every sales message rendered exactly as a parent gets it, and approving is what switches the system on. One render path, so what they approve IS what sends, proven by a committed test. The member-messages approval step parks with skill 4.

Build C
A re-run guard

Re-running a site build currently replaces the client's pages wholesale, which would silently eat any client-requested fixes made since. The build now stops and lists them instead, and staff folds them in deliberately.
