STORY 04An owner who wants different words

Lij thinks the welcome email is too long. What happens now?

There is no free-text box for him to edit it in. That is deliberate, and here is the flow it creates instead.

   Lij raises a support ticket:
   "The welcome email is too long, can we cut the training habits section?"
                       │
                       ▼
   Staff reads it and asks ONE question:
   is this true for every academy, or only for San Jose?
                       │
          ┌────────────┴────────────┐
          ▼                         ▼
    TRUE FOR EVERYONE          ONLY SAN JOSE
Edit the master

Every academy gets the shorter email, including the ones onboarding next month. The improvement compounds instead of being trapped in one account. This is the path that was supposed to happen for GTA's six emails and never did.

Record a divergence

San Jose's version is marked local with Lij's reason written down. It never gets promoted, never reports as drift, and resurfaces the next time someone asks the same question.

The point of routing it through a ticket

A free-text box would let Lij improve the copy and nobody would ever find out. The ticket forces the one judgment that matters, at the moment somebody is already paying attention. It is the promote-back rule that was written in a code comment and never enforced, turned into a step a human actually takes.

SUMMARYOne rule under all four
No fact, no output.

A block with no fact does not render. A quote block with no connected reviews does not render. A review button with no link does not render. An agent fact we do not hold is absent from the prompt. Nothing ever falls back to another academy's version of it, which is the single failure that produced every problem in this plan.

San Jose's rows were read live: 6 automations seeded, all dormant pending approval, all fully tokenized, and nurture step 3 already disabled as the deliberate hold. That hold has to survive whatever the seeding does, which is why re-seeding is a diff-and-patch, never a delete-and-recreate.
