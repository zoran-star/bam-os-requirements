How the money model works

Companion to money-model-plan.md and the mockups page. What gets built, who it serves, and how every piece of data connects. Infrastructure only: no academy is changed until each one is switched on deliberately.

The one rule everything hangs off: a parent is never told a number that is not what their card gets charged. Plan prices already work this way (shipped 2026-07-24). This plan extends the same guarantee to tax, one-time fees, and discounts.

1The three builds, in order

BUILD T · TAX TEMPLATE set once per academy: "HST, 13%" or nothing | every price and fee just flips taxable yes/no | retires the free-text fees box (the $40 trap) v BUILD S · SIGN-UP FEE one-time, per athlete, pre-tax + own taxable flag | commitments waive it by default, toggle to charge | charged once on the first invoice, never renewals v BUILD C · COUPON APPLICABILITY each code picks the prices AND fees it touches unchecked lines are never discounted

The order is strict. The fee's taxable flag points at T's template; building S first would create a second free-text box that T would then have to migrate. C needs the fee to exist as its own Stripe product before a coupon can target or skip it.

Plug-n-play discipline: the fields, the math, and the surfaces are master structure, identical for every academy on the free-trial sales system. Only the values differ per academy. No academy ever gets a structural fork.

3How the data ties together

Four surfaces, one source. The enroll card, the checkout summary, the Stripe invoice, and the agent's brain all read the same fields through the same function, so they cannot disagree. Change the fee in the wizard and all four update together, the agent within about a minute.

4User stories

Academy owner, onboarding

As an academy owner anywhere, I set my sales tax once, whatever it is called and whatever the rate (HST 13%, a state sales tax, or none), so every taxable price I ever create charges the right total without me typing tax math again.

Build T. Today "13% HST" is retyped on every plan and every commitment, as free text.

Academy owner, pricing

As an owner with a $40 sign-up fee, I want a real one-time fee field, so the fee cannot accidentally become a recurring charge.

Build S. The only lookalike field today repeats on every payment: $40 typed there bills 13 times a year.

Academy owner, strategy

As an owner, I decide per commitment whether the fee is charged or waived. Nothing is assumed for me: I set it, and waiving it on the 3 or 6 month option is my way of nudging parents toward committing.

Build S. An explicit choice on every commitment. A commitment with no choice made charges nothing extra, so an unconfigured offer can never surprise anyone.

Parent, enrolling

As a parent, I see "due today $215, then $175 every 4 weeks" before I enter my card, so the first charge never surprises me.

Builds T + S. The mis-quote gap between what was said and what was billed is the original sin this whole effort fixes.

Parent, two kids

As a parent enrolling two athletes, each enrollment carries its own fee, so the per-athlete rule needs no special handling.

Confirmed per athlete. One enrollment = one athlete in checkout already, so siblings = two checkouts = two fees, automatically.

Academy owner, setting a coupon

As an academy owner, when I create a discount code I tick exactly which of my prices and fees it touches, so my 50% code never silently halves a fee it was not meant to.

Build C. Today a coupon hits every line on the invoice with no way to say otherwise.

Sales agent (already live)

As the booking agent, I quote from the same fields checkout charges, so "what does it cost to start" gets the fee-inclusive answer, per my disclosure policy.

The agent side shipped 2026-07-24. Builds T + S extend what flows into its pricing fact; nothing about the agent changes again.

BAM, rollout

As BAM, I switch each academy on deliberately, so shipping the infrastructure changes nobody's charges on day one.

Rollout rule. GTA migrates its typed "13% HST" to the template with amounts unchanged; San Jose gets its $40 entered only when its price catalog is seeded and checked.

5What cannot go wrong by design

RiskWhy it is closed
fee bills foreverThe one-time fee is an invoice line on the first payment only, never part of the recurring price. The free-text box that made this possible retires with Build T.
agent says the wrong totalThe agent's fact renders through the same money function as the charge. No routable price, no quote: it stays silent and flags admin.
coupon over-discountsCodes only touch checked lines, enforced by Stripe itself (product targeting), not by copy.
academy forks the structureFields and math are BAM master. An academy can change its values, never the shape. Reusing the sales system in a new preset carries everything along.
ship day changes chargesNothing applies until an academy is switched on. GTA's migration is amount-identical; San Jose starts from zero.
